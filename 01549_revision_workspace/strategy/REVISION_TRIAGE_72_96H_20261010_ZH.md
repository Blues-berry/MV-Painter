**3. 立即修正的一处确认错误**

当前主文 Table `tab:cross-interface` 的 MVDiffusion 行，在本次读取时第 505 行写：L–LLH 比 G–FL 的 CIEDE2000 更低，差值 −1.373。这是把 benefit-oriented 统计量读成原始 A−B。

**4. 实验的执行顺序与止损条件**

A. **先做真实模型复现检查，2–4 小时以内有决定。**

GeoTex 与 MV-Adapter 都先选 3–5 个预先指定的 sentinel，不按新生成结果选样。记录源图/条件图、camera、目标/foreground mask、checkpoint 和 base-model 内容身份、运行环境、初始 latent 及 scheduler 初始缩放。GeoTex 对 C3/GFL 的同环境重复和历史输出重放分别检查；MV-Adapter 对官方未修改管线、打补丁但恒定 scale=1 管线、官方重复运行三者检查。每个独立条件重新初始化相同 RNG 状态。

需要的是原生管线的一致性及重复误差基线，不是一味要求两个不同 backbone 的数值幅度完全相同。若官方本身有非确定性，报告其误差和补丁增加的误差；没有证据支持的“允许误差阈值”不能事后发明。

只检查 1 个 GeoTex 对象与历史 PNG 相同，不足以保证后续 300 个对象跨运行栈一致。历史 manifest 缺失依赖版本，已有 tensor trace 证明相同输入 hash 不能排除 scheduler 初始缩放的浮点分歧。如果新栈不能重放，所有需要比较的条件在同一新运行栈一起生成；不能直接把三个新条件拼入旧 C3。保留历史 Fresh C 的内部配对结果作为旧实例。

B. **R2 优先：MV-Adapter 的直接时间调度对照，目标 0.5–1 天。**

官方项目已有 image+geometry 多视角生成路径： https://github.com/huanngzh/MV-Adapter 。在实际使用的 checkpoint 和几何特征路径上做介入即可。不同残差拓扑需要解释，但它并不使所有第二 backbone 实验自动失效。要区分“在独立 backbone 上评估相同调度思想”和“证明相同数字 C3 普遍获益”；后一种才是尚不能成立的强命题。

一致性通过后，沿用已验证的低/高范围，避免测试集上重新扫参。建议最小面板：native default、fixed low、fixed applied mean、Early-high、Middle-high/C3-shaped、Late-high、Generic Linear。高值与 native 相同时可合并重复条件。先锁定 48–76 个完整几何、输入可用的物体；同一 cohort 的所有结果都报告。旧 76 个对象已被看过，重用属于回顾性 follow-up，不改名为新独立确认；若有现成未用输入，才考虑独立 cohort，不因追求标签新建数据工程。

时间高段统一 16 步，其余 34 步 low；固定均值按实际 50 步计算。举例 low=0.75、high=1.00 时，均值应为 0.83，而非机械写 5/6。各 backbone 在自己的 cap 之后核对 scale 总和。用 FG-PSNR/FG-LPIPS/FG-SSIM/Edge-SSIM，再加入可复核 ΔE00；以物体为配对单位，给均值、区间、中位数、胜率。锁定一个主要比较，其余成一组校正；展示失败实例。

通过标准是得到完整、可解释、正负均报告的第二 backbone 结果，不是必须让 C3 赢。若不迁移，回复应该明确报告“我们新增了检验，结果未支持通用迁移”；这完成了实验请求，但仍会削弱通用方法优势，不能称科学上已证明泛化。

若原生一致性 4–6 小时内仍不能定位原因，停止扩大该实验；保留当前接口分析并说明剩余限制。不要把第二天耗在重新训练第二 backbone。

C. **R1 优先：全物体/native-default 对照与小型烘焙 pilot，CPU 准备并行，目标 0.5–1 天。**

最容易漏掉的是 **No Adapter≠native default**。审稿人要求 unmodified pipeline：必须运行原生未改变的默认 path，记录默认 scale/cap；不能用 scale=0 或未经证明的 scale=1 数字代替。如果 native 与某固定条件相同，先验证再合并标签。

全物体面板建议 12 个预先锁定的物体：按 GT 纹理复杂度分层抽取，选择规则在打开新结果前固定，另单列原 Fig.4 两个失败例。列为 Reference、Native、No Adapter、GFL、GFH、C3、Linear。至少包含输入参考视角与多个目标视角。提供完整对象和固定 ROI，使用相同曝光/背景/缩放，不人为增饱和度或把目标颜色用于修复。既有 outcome-selected 例子可以保留，但不能称代表性抽样。

本次视觉复核中，当前 Fig.7 的有利案例参考是建筑样式，而各生成列呈岩石纹理。即使其中 C3 数值好于 GFL，也不能作为参考外观改善的视觉证据。应明确区分具名数值优势、偏好和外观重建，展示源图身份与失败。

旧 Fresh C N=24 bake 的失败需保留。另建一个预先定义的可行性限定 pilot：8–12 个技术条件可支持的资产，按 alpha/sampler/几何可读性等输入条件筛选，随后固定名单；报告筛掉哪些和原因。它是小规模 downstream 验证，不是取代原 N=24 或 population-level 确证。最小条件 Native、GFL、GFH、C3；有预算加 Linear。

先用 1–2 个物体检查真实 GLB 的几何/坐标、相机、UV/sampler/alpha、导出后再导入和重复渲染。合成采样器通过不能替代真实资产检查。原生 UV、REPEAT、BLEND 是需要正确处理的渲染语义，不是模型失败；如果当前软件不支持，则限定技术范围。共同且正确的 UV 重展是合法的生成烘焙步骤，但必须在新 pilot 的方案中明确，所有方法共享同一几何/UV布局，GT 原始外观在其正确材质下单独渲染；不能把改变 GT 材质/UV 后的图继续叫原始参考，也不能假称保持原 UV。

先做 unlit/base-color unseen-view 渲染：固定 8–12 个没有作为生成目标的相机，按每物体平均后给 ΔE00、LPIPS、必要的前景 PSNR。低样本只能给有限证据和区间。接缝可先做具名的 seam/cross-view visual audit；如没有验证好的数值端点，就不发明一个分数。若要量化，须先验证相邻表面采样和参考自然纹理边界，不能简单把所有色差计为接缝。共享 mesh 上多个角度更平滑不等于比 GT 更忠实。

R1 没有要求完整 PBR 研究。本轮不要为“全 PBR”、HDR 光照 sweep 或新物理材质系统消耗两天。0.5 天内真实资产 pipeline 不通，停止这一 pilot，报告已有 N=20 unlit 小样本与真实局限，不将失败的 24 例包装成成功。

D. **GeoTex 等 applied-scale 总和对照：作为贡献补强，放在上述两项后。**

实验 agent 已准备 Fixed Applied Mean、Early-high、Late-high 的三个新条件。C3 的高段为 17–32，Early 为 0–15，Late 为 34–49，各 16 步；三个 profile 的 deep/middle scale 总和是 82.5，shallow 是 40，fixed mean 请求 1.65。CPU 真实 wrapper 控制路径检查通过，但尚不是真实 UNet 的 cohort-level 结果。

这项能回答“是否只因为平均 scale 更大”，但不能保证 Middle 最佳，也不能证明 equal realized residual dose。实际残差 norm 是受生成轨迹影响的过程量，不要把等输入 scale 实验变成必须先实现跨组 realized-dose overlap 的不可完成工程。直接报告 scale 控制后的 stage placement 结果及残差曲线，并保留该解释限度即可。

先过 A 的复现检查。可可靠重放时，补 300×3=900 次生成；不能重放则同栈重跑相关 6 条件，或预先锁定较小的完整配对 cohort 并标为回顾性 pilot。不能在结果出现后只选获益对象。若补参后早/晚更好，保留 C3 作为旧历史选型，报告它并非优选；不要将 LLH 改名为 C3 或重启 schedule sweep。

从 B2 的 8 次调用/77.3 秒估算，GeoTex 每对象×条件约 9.7 秒，仅 sampler 的 900 次约 2.4 GPU 小时、1800 次约 4.8 GPU 小时；这是相似开发运行的下限参考，不是该新任务的承诺。启动、数据读取、模型加载、评估和新的 peak VRAM 用 3–5 对象实测后另计。GPU 可分配成一张 MV-Adapter、一张 GeoTex；同一张卡不叠加未知任务。

**6. 论文应该怎样改**

标题暂时保留 TCAS；不再创建 On Adapter Scaling / L-TCAS 等另一个稿件身份。C3 的数学定义保留。CAI 改成历史动机/描述，删除 theorem、独立推导、唯一最佳的含义；不写新理论来补旧结果。

主论证顺序建议：几何控制改变结构与外观 → 实际 scale/cap 与请求值不同 → held-out 固定/调度对照 → 对象和指标 trade-off → 第二 backbone 的迁移或不迁移 → 有限 downstream 可用性。不要让正文变成每段都在解释历史审计事故；具体 hash、旧运行 chronology 和完整失败追踪集中在 Supplement。

摘要保留问题、简单干预、具名 held-out 结果与一个重要限制。+0.522 必须明确是 C3 对 GFL 的 FG-PSNR；不把原 +0.96 full-image PSNR 换一个数后继续称复验。Generic Linear/GFH 的反例在摘要简短可见，在主表完整展示。若新等 scale/第二 backbone 对照有明确结果，摘要用该结果补贡献，不能先写。

主文用四个核心展示承载论证：控制路径与 cap 图；完整 held-out 对照表（含 Linear/GFH）；预锁全对象/失败图；第二 backbone 结果及小型 downstream 结果。原图表按论证作用保留或移入 Supplement，不能因保护原稿而让无法追溯的旧 heatmap/probe 主导目前证据，也不能无记录把大部分图表删除。

“LHL/C3”表示时间三阶段。Fresh C 的 layer-conditioned LLH 与 strict-276 的 temporal L–L–H 是不同操作，必须用完整定义和表头区分，不能并成一个“LLH 胜出”的方法。

全篇措辞：variation≠fidelity；参考色差只是具名的 image-space color agreement；主观偏好≠绝对保真；CI 跨零≠等效/非劣效；未发现交互≠不存在交互；实际 scale 总和相等≠实际 residual dose 相等。选择改变保存声明而不是事后挑一个 non-inferiority margin。

贡献定位可以是有实用价值的 adapter 控制实证研究，但“我们做了审计/记录 hash”本身不足以回答 R2。必须让读者知道这套测量改变了什么实际结论：哪些基线更好、何时失效、是否迁移、为何 image metrics 不足以保证 baked appearance。SSI 已研究层/时间调度与几何 ControlNet strength；公开主源 https://arxiv.org/html/2605.26538v1 支持这一点。不要以调度轴为首创；引用格式也应核对单作者信息，当前 `Kulkarni A S, et al.` 不应未经核对保留。

**10. 提交判断**

技术完整性与科学充分性分开判断。前者包括 clean/marked/Supplement/response 一致、数据符号与区间准确、源码可重建、视频可访问。后者包括主论断能否经受 GFH/Linear 反例、第二 backbone 的评估是否有效、downstream 证据范围是否清楚。

最佳可行场景：第二 backbone 的时间干预有可解释结果，小型 native/bake pilot 可运行，等 scale 对照又支持一个有用的有限结论。此时可以形成一篇有实证增量的有限方法/系统研究。
