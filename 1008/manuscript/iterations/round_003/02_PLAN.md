# 第三轮冻结计划

1. 保存独立第三轮源文件；前两轮不覆盖。
2. 同两个已见UID，复用前轮实际conditioning batch及seed；核对conditioning tensor hash。直接加载同一base模型资产，保持裸UNet→原生prepare→完整pipeline；不加载GeoTex权重，不绑定几何残差。
3. 四次调用：原生base默认50步，以及75步敏感性，各两对象；原生512视图、在线图像embedding、CFG2和原生scheduler。记录输入、实际UNet调用、scheduler、起始latent、输出hash、GPU和源码身份。
4. 全六视图和conditioning图完整展示，使用已有输入顺序，不挑优图。未核准完整路径相机约定前不对六视图计算配对GT图像指标。只报告执行、颜色/形状失败诊断及协议差异；无显著性检验。
5. 据输出决定后续优先级；有路径问题才修复，有明确质量收益才设计扩大验证。本轮不把诊断当新算法或解决R2.1的证据。更新独立正文/补充/回复并编译验证。

## 执行前有效性修正（首尝试零输出）

原生API的recenter_img要求RGBA，RGB首尝试在生成前失败，保留原始失败目录。第二尝试使用相同已冻结UID的原始单条件RGBA源图，记录来源hash与原生预处理后的图像；对象、条件、步数和统计定位不变。原pipeline会原地修改部分亮色前景RGB，因此不声称其实际条件特征与受控采样相同。之前batch条件tensor仍复算并核对hash，用于确认来源对应，而非证明完整预处理等价。
