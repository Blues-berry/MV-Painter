# 01549 main adapter vs Fresh C: experiment identity audit

**Date:** 2026-10-08  
**Historical identity finding:** Fresh C is a UID-disjoint held-out evaluation of one frozen controlled-retraining checkpoint in the GeoTex-adapter family. It is not a byte-identical reproduction of the historical v1 Table 4 experiment. The official 01549 package separately identifies v1 main-table and v2 Section 4.7/FAC runs.  
**Author-confirmed R1.2 interpretation:** Fresh C is the primary second-round held-out evidence because its conditions are matched within one checkpoint, runner, cohort, inputs, seed policy, endpoint, and cap semantics. Exact checkpoint hash identity with historical Table 4 is not a blocking gate. This audit records historical differences, not an R1.2 closure blocker.

## 2. Gate results

| Required identity judgment | Result | Reason |
|---|---|---|
| `SAME_CHECKPOINT` | **NO** | Original v1 checkpoint is not present at the paper's recorded path and has no hash in the submitted source; Fresh C SHA is a controlled retraining. |
| `SAME_ADAPTER_IMPLEMENTATION` | **PARTIAL** | Same GeoTex residual-adapter family and related implementation, but the original runtime source/hook list is not tied to the submitted main run. |
| `SAME_SCALE_SEMANTICS` | **UNVERIFIED** | Fresh C cap behavior is logged; original main experiment does not provide enough runtime detail to establish the same applied-scale rule. |
| `SAME_INPUT_PROTOCOL` | **PARTIAL** | Same general six-view/50-step matched-comparison concept, but new disjoint objects, per-object seeds 42+i, and different source/input hashes. |
| `SAME_ENDPOINT_DEFINITION` | **UNVERIFIED** | Fresh C foreground PSNR implementation is hash-pinned; old Table 4's PSNR implementation is not run-bound, so equivalence cannot be proved. |
| `DIRECT_MAIN_ADAPTER_REPLICATION_VALID` | **NO** | The checkpoint differs, exact cap/hook semantics are not verified, and endpoint equivalence is unverified. |

Fresh C's primary integrity gate passes: 300 objects × four primary conditions = 1,200/1,200 rows; each condition covers 300/300 objects and all rows pass shared-input, finite-output and hash gates. The same-cohort addendum gate passes for 600/600 rows. Together with the author-confirmed shared checkpoint/runner/input/metric/seed protocol, this is the second-round R1.2 evidence. It remains distinct from the historical Table 4 weights and old +0.96 dB estimate.

## 3. Historical exact-reproduction boundary (optional, not an R1.2 gate)

1. First recover and SHA-256 freeze the original `geotex_refattn_v1/geotex_step_0002000.pt`, its source/config, and the historical runner or a verified equivalent. If the original checkpoint cannot be recovered, an exact same-checkpoint confirmation is not possible; do not substitute the controlled-retraining file.
2. Reuse the 300 Fresh C UIDs only after freezing their input manifest and confirming no overlap with training or the original probe. Run the exact recovered main adapter on No Adapter, the historical conservative fixed scale, aggressive fixed scale 2.50, and C3; use common per-object geometry, views, latents and seed within each condition comparison.
3. Predeclare the primary object-level contrast C3 vs fixed 2.50; compute the original PSNR definition from its recovered code and report FG-PSNR separately if the two differ. Include paired object bootstrap intervals, row-level IDs, outputs and a full run manifest.
4. Resource estimate for planning only: 1,200 object-condition generations at 50 denoising steps; reserve about 0.5–1 GPU-day on a single available 24 GB-class GPU, then revise using measured throughput from a small authorized benchmark. This is not a measured runtime. **No run is authorized or started by this audit.**

## 4. Manuscript consequence

Describe Fresh C as a disjoint-cohort, matched image-space evaluation under one frozen checkpoint, runner source, input/metric protocol, seed policy, and actual cap semantics. Keep the historical v1/v2 differences and the non-reproduction of the old +0.96 dB number clear. Do not make exact original-checkpoint identity an R1.2 gate; it is a separate historical limitation.
