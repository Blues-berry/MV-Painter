## What the rows show

- Fresh B contains 150 UIDs. They exactly match the frozen 150-UID list already in main, have no UID overlap with diagnostic-26, and all 150 paired GFL/LLH rows pass the six-input-hash equality audit. Checkpoint, runner, and config identities are constant within the cohort.
- The archived LLH per-object PSNR, LPIPS, SSIM, and Edge-SSIM rows match main's retained Fresh B `layer_llh_per_object_metrics.csv` exactly. The archived `native_gfl` control is not the same as main's `a3_baseline`: its per-object metrics differ, so the two controls are not substituted for one another.
- Reaggregation from the 150 paired rows reproduces the saved Fresh B means, favorable counts, and four main 95% intervals exactly when the per-output seeds recorded in the statistics CSV are used: CIEDE2000 −1.905396 [−3.262021, −0.528993] (85/150 lower); FG-PSNR +1.030130 [0.577497, 1.492532] (77/150 higher); FG-LPIPS −0.015557 [−0.019196, −0.011921] (111/150 lower); GT-relative Laplacian error −0.018712 [−0.020156, −0.017434] (150/150 lower).
- In the GT-defined Fresh B Q4 stratum (`n=38`), LLH minus GFL is +3.624043 CIEDE2000 [1.906729, 5.303152] (10/38 lower) and −0.769594 dB FG-PSNR [−1.165335, −0.315401] (7/38 higher). The LPIPS interval spans zero. Means, intervals, and win counts for these three Q4 values reproduce from the saved per-object rows and the script's deterministic seeds. This is an object-complexity boundary alongside a cohort-average result, not a uniform fidelity claim.
- The comparison is `layer_llh` versus `native_gfl`, not C3 versus GFL. The schedules have different requested/applied residual doses. It does not establish a dose-adjusted schedule effect, a universal schedule winner, physical color accuracy, or a validated color correction. The separate C1/B2 color-repair gates remain failed in the current main evidence.

## Chronology and analysis limits

The protocol JSON reports `locked_at_utc=2026-10-08T22:20:00Z`, but Git first records the protocol, analysis outputs, and report together in commit `8f6de4b959fb1b34151df4d02a0c8d577010fea1` at 14:52:59Z; the source's closeout report says approximately 14:55Z. Git cannot establish that the analysis lock preceded result inspection, and the recorded lock time is later than the commit/closeout timestamps. Treat these reanalyses, including the Fresh B quartile result, as retrospective sensitivity evidence, not preregistered confirmation.

The protocol says one bootstrap seed (`20261008`), while the analysis script and output use a deterministic incremented seed per statistic; Fresh B's CIEDE/PSNR/LPIPS/Laplacian rows use seeds `20261028`, `20261029`, `20261030`, and `20261033`. The saved intervals reproduce from the recorded seeds. This documentation discrepancy should be resolved before quoting any interval as protocol-locked. Campaign manifests omit the inference package versions. The first pixel-pooled CIEDE table is explicitly superseded and excluded from the reported results.
