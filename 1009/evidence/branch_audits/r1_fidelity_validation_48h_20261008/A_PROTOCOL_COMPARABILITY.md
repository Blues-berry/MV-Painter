## Scale and residual audit

GFL requests deep/middle/shallow scales of `1.25` throughout all 50 steps. Applied scales are deep `1.25`, middle `1.25`, shallow `0.80` because of the shallow cap. LLH uses steps 0–16 and 17–32 at deep/middle `1.25`, shallow `0.50`; steps 33–49 use deep/middle `2.50`, shallow `0.75`. These values are below the respective caps, so the LLH effective scales equal the requests.

The arithmetic mean requested LLH scale is `1.675` for deep/middle and `0.585` for shallow, versus `1.25` and `0.80` for GFL. Thus GFL and LLH are not equal-dose controls. The paired residual-log summary confirms the expected pattern in both cohorts: early/middle shallow effective scale averages `0.50` for LLH versus `0.80` for GFL; late deep/middle averages `2.50` versus `1.25`. Logged late deep/middle mean-absolute residuals approximately double. These logs describe the realized schedule and do not identify a color mechanism by themselves. Per-object log hashes and the UID/input join are in `RESIDUAL_LOG_IDENTITY_AUDIT.csv`; object-step pairs and cohort summaries are in `RESIDUAL_LOG_STEP_PAIRED.csv` and `RESIDUAL_LOG_STEP_SUMMARY.csv`.

The shared model checkpoint includes the adapter weights and has the same SHA-256 for Fresh C, Fresh B, and diagnostic-26. The campaign manifests also point to the same A3 normalization spec (`a3_normalization.json`, SHA-256 `fdf2987b7931f71e15efa47f2012148e5509cfde25cf85169329b48e884b6c4b`); condition-specific requested scales and applied caps are recorded in each run manifest. The base runner and config hashes match. Therefore, the paired GFL/LLH difference is a difference in adapter application schedule under the same checkpoint weights, not a checkpoint swap.

The source panels are never assigned metrics from a different UID or run instance.

## Metric-source comparability

`fg_ciede2000_rgb` and signed mean Δa*/Δb* are recalculated from saved 8-bit RGB and the frozen target foreground masks; each of six view means has equal weight, matching the prior R1 diagnostic definition. Target panels use the frozen white-background RGBA composite, unique6 ordering, 90° target-slot rotations when required, and antialiased bicubic resize to 256. The first pixel-pooled CIEDE pass is superseded and excluded; the method change is recorded in `ANALYSIS_METHOD_CHANGELOG.md`.

FG-PSNR, FG-LPIPS, FG-SSIM and Edge-SSIM are the exact UID/condition rows from each campaign's saved per-object metrics CSV. GT-relative Laplacian error is recomputed from the saved PNG, reconstructed target and eroded GT mask in this analysis runtime. The Fresh C GT-only complexity fields use the same definitions as `geotex.metrics_extended`; the reconstruction was cross-checked on all 150 Fresh B objects against the frozen official columns (maximum absolute difference below `3×10⁻⁷` across RGB standard deviation, gradient magnitude, Laplacian variance and HF energy). Cut points are fixed from Fresh B's GT Laplacian-variance quartiles and are not re-tuned on output deltas.

No cross-cohort pooled estimate is used. Bootstrap resampling is over paired object UIDs within the named cohort, 10,000 draws, two-sided percentile intervals. Fresh C cross-cohort quartile and continuous-complexity results are labeled exploratory. Signed Lab changes are reported as color-vector diagnostics, not assigned a one-direction “win.”
