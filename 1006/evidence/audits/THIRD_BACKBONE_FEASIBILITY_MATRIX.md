# Third-backbone feasibility matrix — 2026-10-05

## Decision

**Decision: `DO_NOT_RUN — technically unjustified`.** The search found architectures with useful multi-view geometry conditioning, but none meets all frozen requirements at once: a public frozen checkpoint, no per-object training/optimization, a directly exposed additive residual scale, and a comparable geometry-to-multiview input path reproducible within two days. No model or cohort was selected, and no third-backbone outcome was generated.

This does not resolve the dose-identification limitation in A3b. It means the paper must state the current backbone boundary: the GeoTex response surface is not demonstrated to transfer universally, and MV-Adapter's interaction result remains exploratory/non-confirmatory under its frozen scale range.

## Candidate assessment

| Candidate | Architecture and task fit | Frozen checkpoint / deployment | Direct additive control | Decision |
|---|---|---|---|---|
| 3D-Adapter / MVEdit | 3D feedback module re-encodes geometry-consistent multi-view features and adds them to a pretrained image diffusion model; the project demonstrates text-to-texture and image-to-3D tasks. It is a genuinely different feedback architecture. | The official repository documents an optimization-based variant built from off-the-shelf models and a separate GRM-based variant whose models are not released. The UI needs at least 24 GB VRAM and downloads models on first run. It does not provide a pinned frozen adapter checkpoint plus the exact mesh-conditioned scale experiment needed here. | Paper describes feature addition, but no verified per-layer/per-step residual-scale interface is exposed in the released inference flow. Adding and validating a multiplier would be an unplanned external-code modification. | **Closest candidate; no-go for this revision.** Public code and architecture are promising, but the fixed-checkpoint and direct-control requirements are not met cleanly. [Official repository](https://github.com/Lakonik/MVEdit), [project/paper](https://hanshengchen.com/3d-adapter/) |
| ConsistNet | Geometry-aware 3D feature aggregation generates a residual feature map for each view and adds it to decoder layers; highly relevant architecture and a frozen Zero123-XL base in the paper. | The official repository lists the pretrained model as “Coming soon”; the paper's checkpoint is not available from the project page. | The residual is conceptually additive, but the required trained plug-in weights are unavailable. | **No-go.** Strong architecture fit; fails the public frozen-checkpoint gate. [Official repository](https://github.com/JiayuYANG/ConsistNet), [CVPR paper](https://openaccess.thecvf.com/content/CVPR2024/papers/Yang_ConsistNet_Enforcing_3D_Consistency_for_Multi-view_Images_Diffusion_CVPR_2024_paper.pdf) |
| MVDiffusion | Geometry-conditioned depth-to-image generation can texture scene meshes using camera/depth inputs and correspondence-aware attention. | Official weights and code are available, but the geometry model was trained on ScanNet and its released inference path consumes depth/camera sequences. | Correspondence-aware attention and resizing layers are the control mechanism; there is no isolated additive geometry residual scale to sweep. A newly trained control would violate the no-training constraint. | **No-go.** Useful interface-boundary reference, not a compatible additive-residual backbone. [Official repository](https://github.com/Tangshitao/MVDiffusion), [project page](https://mvdiffusion.github.io/index.html) |
| SyncDreamer | Synchronized multi-view images from a single input image; separate NeRF/NeuS reconstruction is needed for a 3D output. | Inference code and pretrained models are public. The official instructions note output-set selection and downstream reconstruction/training steps. | Synchronized denoising is intrinsic to its generation model; no mesh-conditioned additive residual control is exposed. | **No-go.** Different task interface and no matching residual control. [Official repository](https://github.com/liuyuan-pal/SyncDreamer) |
| Wonder3D | Cross-domain diffusion generates color and normal maps, then fuses normals to reconstruct a textured mesh from a single image. | Public inference code and weights are available. | The intervention would change color/normal generation or fusion, not scale a geometry residual injected into a geometry-conditioned multi-view adapter. | **No-go.** Not comparable to the frozen intervention family. [Official repository](https://github.com/xxlong0/Wonder3D) |

## Selection rule and experiment status

No candidate passes every frozen gate, so selecting one would require changing the target intervention or treating unpinned test-time optimization as a fixed model. Neither would be a clean third-backbone confirmation. Do not substitute MVDiffusion as an additive-residual model; retain it only as interface-boundary evidence.

If a later study is authorized, re-open the matrix only after a candidate has (1) a hash-pinned public checkpoint, (2) an auditable additive residual tensor with a frozen scale hook, (3) geometry-conditioned multi-view outputs without training or per-object model fitting, and (4) a successful dry run on the exact 6-condition design. Freeze the chosen candidate and fresh-object list before outcomes.

## Primary sources checked

- 3D-Adapter project describes per-denoising-step 3D feature feedback added to the base model; its repository documents the optimization-based path, unreleased GRM models, and runtime setup: [project page](https://hanshengchen.com/3d-adapter/), [official code](https://github.com/Lakonik/MVEdit).
- ConsistNet's paper describes a per-view residual feature added to decoder layers, while its official repository still marks pretrained weights as forthcoming: [CVPR paper](https://openaccess.thecvf.com/content/CVPR2024/papers/Yang_ConsistNet_Enforcing_3D_Consistency_for_Multi-view_Images_Diffusion_CVPR_2024_paper.pdf), [official code](https://github.com/JiayuYANG/ConsistNet).
- MVDiffusion's official project defines the depth-conditioned mesh-texturing path and correspondence-aware attention: [project page](https://mvdiffusion.github.io/index.html), [official code](https://github.com/Tangshitao/MVDiffusion).
- SyncDreamer documents single-image-conditioned multiview output and subsequent NeRF/NeuS reconstruction: [official code](https://github.com/liuyuan-pal/SyncDreamer).
- Wonder3D documents color/normal multi-view generation followed by normal fusion: [official code](https://github.com/xxlong0/Wonder3D).
