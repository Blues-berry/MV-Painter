# D 12-object CPU Bake Validation Audit

Audit date: 2026-09-29 UTC

## Result

Status: `PASS_WITH_LIMITATIONS` for real Exact-GLB bake and unseen-view
implementation evidence. This is not a population-level TCAS advantage claim.

## Direct checks

- `BAKE_RUN_SUMMARY.json`: 12 frozen Exact objects × 4 generated methods = 48
  bake records.
- `UNSEEN_OBJECT_METRICS.csv`: 48 object rows.
- `UNSEEN_PER_VIEW_METRICS.csv`: 528 rows = 12 × 4 × 11 views.
- Every record has an exported textured GLB, texture PNG, coverage PNG,
  inpainted-coverage PNG, and 11 unseen renders.
- All required source-view sets are `{0, 12, 13, 14, 15, 16}`. Three objects
  use the permitted reversed mapping `[14, 15, 0, 16, 12, 13]`; this is not a
  protocol error because the handoff records per-object view orientation.
- All audited numerical fields are finite. LPIPS AlexNet ran on CPU. DISTS was
  unavailable because `DISTS_pytorch` is not installed, so no DISTS claim is
  released.
- Spot inspection was performed on generated unseen renders and a baked UV
  texture, including `obj_0015` and `obj_0048`.
- The GT-to-GT smoke passed for camera/UV/visibility sanity (`obj_0015`
  masked PSNR 42.3589 dB, silhouette IoU 0.9999167; `obj_0013` masked PSNR
  30.8646 dB, silhouette IoU 0.9996277). Generated renders show visible
  color/cross-view source-fusion inconsistency; this is a
  `COLOR/SOURCE-FUSION` limitation, not evidence of a camera, UV, visibility,
  or rasterization failure.

## GLB/UV audit

Blender 4.2.4 imported all 12 input GLBs and all 48 exported GLBs. Across the
48 pairs:

- mesh-object count is preserved;
- polygon counts are preserved;
- UV layer names, loop counts, unique-UV counts and recorded UV bounds are
  preserved;
- the bake implementation verifies an embedded exported image texture;
- all methods for an object share the same exported geometry/UV arrays under
  the bake script's cross-method check.

One exporter limitation is material to the wording. For `obj_0048`, Blender's
glTF round-trip reindexed/deduplicated vertices in several mesh components.
The polygon counts and UV loop data remain unchanged, while vertex counts for
some components and the world bounding box differ at exporter precision. This
is semantic geometry/UV preservation for the rendered bake, not a byte-level
identity guarantee. The original input GLB bytes were not modified.

## GT sanity scope

The completed `cpu_bake_12` run contains only
`no_adapter,fixed_low,fixed_high,c3`; it does not contain a `gt` bake. The
actual GT-to-GT bake sanity evidence is the earlier two-object smoke
(`cpu_bake_smoke_final`) with two objects and five methods including `gt`.
The `cpu_bake_12/UNSEEN_METRICS_SUMMARY.json` field
`gt_to_gt_sanity_rows: 12` is therefore bookkeeping generated by the evaluator,
not evidence of twelve GT bake records, and must not be quoted as such.

## Scientific boundary

The output proves a real CPU Exact-GLB baking and unseen-view rendering path
for a fixed, stratified 12-object case-study cohort. It does not establish:

- a 276-object or 300-object 3D population estimate;
- a TCAS advantage over fixed-low or no-adapter;
- DISTS-based fidelity;
- byte-identical mesh export after Blender glTF reindexing;
- unbiased generalization from the stratified cohort.
- generated texture fidelity or cross-view appearance superiority; the
  generated-source color disagreement must be reported.
